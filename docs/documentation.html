The terminal is the starting point. Here are the controls underneath it.

Start a session

Install a release, choose a provider, and launch Habibi from your project. The installer verifies checksums and installs atomically to ~/.local/bin; add it to PATH if prompted. Checksums detect corruption, not an independent publisher identity.

curl -fsSL https://habibiailabs.github.io/habibi-code/install.sh | sh

Read the installer first or download an archive. Run the installer again to upgrade, then restart Habibi.

# Codex subscription (experimental)
habibi login codex
habibi --provider codex

# Claude subscription (experimental)
habibi login claude
habibi --provider claude

# Ollama: start the server and install a tool-capable model first
habibi models ollama
habibi --provider ollama --model qwen3:8b

Provider account access and model availability are controlled by the provider. Adapters are experimental, not verified provider-approved integrations. No automatic API-billing fallback is provided. For remote login, paste the callback URL into the private login prompt, never into chat.

Defaults and storage

Use /model and /settings to save defaults. The settings panel controls permissions, context budget, auto-compaction, model-turn cap, MCP, code mode, skills, and status elements. A turn cap of 0 means unlimited. Changes saved during a run apply after it finishes.

Default pathContents
~/.config/habibi/settings.jsonUser defaults; XDG_CONFIG_HOME overrides the config root.
~/.config/habibi/auth/Provider credentials.
~/.config/habibi/mcp.jsonExplicit trusted MCP servers; no project discovery.
~/.config/habibi/mcp-auth/Endpoint-bound MCP OAuth credentials.
~/.local/share/habibi/sessions/Private JSONL journals; XDG_DATA_HOME overrides the data root.

Use /resume to browse sessions for the current folder. A journal can be open in only one instance. Resume restores saved TUI permissions—including YOLO—without a second confirmation. Headless/RPC still require explicit --yolo for auto-approval.

Tools & permissions

File reads, edits, writes, shell execution, and image attachments are built in. /mcp manages trusted stdio and HTTP servers; a authenticates an HTTP server, and connections start on the next prompt. Code mode runs embedded JavaScript to compose tools; child calls still require individual approval.

/secret provides masked entry, memory-only capture, local reveal, and redacted shell execution. This is transcript hygiene, not a sandbox or protection against a malicious model. Private input and reveal require the TUI.

Ask mode is the default. YOLO auto-approves unsandboxed tools and can become the default for future sessions when saved in settings. Configured MCP programs are separately trusted: startup itself does not require a tool approval.

Sticky skills

Habibi discovers Agent Skills from ~/.agents and the workspace’s .agents. Both skills/name/SKILL.md and name/SKILL.md layouts are supported. Workspace skills take precedence.

habibi --skill-dir '~/.agents' --skill-dir .agents --skill-dir ./team-skills
habibi --no-sticky-skills

Type /skill:name to request a discovered skill. Discovery loads metadata; loading a full skill body still requires approval. Sticky mode is on by default: approved snapshots remain active through compaction and session resume, even if the original file moves. Skill metadata and snapshots count toward the context byte budget. Skill content is untrusted reference material, not higher-priority instructions. Nothing is downloaded automatically.

Context & tool inspection

Open /inspect at any time. Context shows the system prompt, skills, tool definitions, and active messages. Tool calls shows recorded arguments, results, errors, and earlier calls—even before compaction.

Tab (or 1/2) switches tabs; arrows select; PgUp/PgDn or wheel scrolls; / searches; a toggles latest/all calls; Esc closes. During a run you see the latest context-boundary snapshot; reopen to refresh. Inspection never executes or approves tools.

Sizes are bytes, not provider tokens or an exact wire-payload estimate. Context is bounded; automatic compaction defaults to 80% of the byte budget and keeps original journal records. Compaction is lossy and requires a working provider.

Rex integration

Habibi natively emits OSC 7501 status (working, blocked, done, error, idle) and authenticated OSC 7577 resume reports. Status messages do not include prompts, paths, tool arguments, or credentials.

Version caveat: published v0.8.0 reports a shell wrapper. The local development fix reports ["habibi", "--resume", "/absolute/journal.jsonl"] directly so Rex can match it to the Habibi process. The rule below requires a build containing that fix. Do not broadly trust sh -c as a workaround.

Enable resume in Rex

Add this scoped rule to your Rex init.lua. Habibi does not change your configuration for you.

rex.set("resume.trust.habibi", {
  command = {
    "habibi",
    "--resume",
    rex.match.under("~/.local/share/habibi/sessions"),
  },
})

With custom XDG_DATA_HOME, use the resolved absolute Habibi session directory. Canonical journal paths must be under that directory; rex.match.under rejects .. and Rex rechecks symlinks before resuming. Keep only trusted journals there: saved permissions are restored too.

The first rule element matches the reported name habibi, not an arbitrary executable path. Ensure the fixed build is on the restored terminal’s PATH. --resume restores the saved workspace itself, so no cd wrapper is required.

rex config check
rex config reload
# Inspect the relevant terminal, not another agent’s block:
rex block call -b "$REX_BLOCK" program_resume_records

Reload applies the rules without restarting Rex. A failed reload keeps the last successful configuration. Check the current journal, program=habibi, and absence of untrusted_reason; chosen=true alone is not proof of trust.

ReasonCheck
no_ruleMissing rule or a journal outside the allowed directory.
program_differsReported program differs from the process; replace the old shell-wrapper build.
config_incompleteRex configuration did not load successfully.

Reports refresh on session switches and SIGCONT. Explicit quit clears the record; terminal loss, SIGHUP, and SIGTERM preserve it. The token is removed before children start. Headless/RPC mode emits no resume reports.

For restart tests use a disposable socket and state directory, isolated configuration, and disposable sessions. A new socket alone does not isolate saved state. Do not restart your daily Rex server or use other agents’ sessions. See Rex’s full rule reference.

Rust API · libhabibi

libhabibi owns the agent loop; the terminal is one frontend. The library does not print, exit the process, discover global configuration, or choose storage paths. Hosts provide a workspace and credential store explicitly. Sessions stay in memory unless persisted.

APIRole
SessionConfig::newChoose a Provider and workspace; configure model, prompt, and preferences.
Session::newConstruct an in-memory session with an explicit AuthStore.
Session::promptRun a turn, stream Event values, and honor a CancellationToken.
Event::PermissionHost decides whether to approve a tool call via its reply channel.
Session::persist / resumeOpt into a journal and restore saved history and configuration.
Tool / ToolDefinitionRegister host tools with validated input schemas and explicit handlers.

A complete minimal host

This repository example streams text and denies every tool. Use your application’s approval UI or explicit policy instead of blindly approving requests.

Show Rust example
//! Run with: cargo run -p libhabibi --example embed -- AUTH_DIRECTORY WORKSPACE PROMPT
//! AUTH_DIRECTORY is Habibi's credential directory, not a credential value.
use anyhow::{Context, Result, ensure};
use libhabibi::{CancellationToken, Event, Provider, Session, SessionConfig, auth::AuthStore};
use std::io::Write;
use tokio::sync::mpsc;

#[tokio::main(flavor = "current_thread")]
async fn main() -> Result<()> {
    let args: Vec<String> = std::env::args().skip(1).collect();
    ensure!(
        args.len() == 3,
        "Usage: embed AUTH_DIRECTORY WORKSPACE PROMPT"
    );
    let config = SessionConfig::new(Provider::Codex, &args[1]);
    let mut session = Session::new(config, AuthStore::new(&args[0]))?;
    let (events, mut stream) = mpsc::channel(64);
    let consumer = tokio::spawn(async move {
        while let Some(event) = stream.recv().await {
            match event {
                Event::TextDelta(text) => {
                    print!("{text}");
                    std::io::stdout().flush()?;
                }
                Event::Permission { call, reply } => {
                    // Replace with your application's explicit approval policy or UI.
                    eprintln!(
                        "Denied {}: this example grants no tool permissions",
                        call.name
                    );
                    let _ = reply.send(false);
                }
                _ => {}
            }
        }
        Ok::<_, std::io::Error>(())
    });
    let cancel = CancellationToken::new();
    let result = session.prompt(args[2].clone(), events, cancel).await;
    consumer.await.context("Event consumer failed")??;
    println!();
    result
}
cargo run -p libhabibi --example embed --   "$HOME/.config/habibi/auth" /path/to/project "Explain this repository"

cargo doc -p libhabibi --no-deps --open

Use the workspace crate when embedding; these instructions do not assume a crates.io release. The Rust API and journal format are experimental and may change. Public modules include auth, MCP, MCP OAuth, tools, skills, secrets, and Ollama support.

Headless & stdio RPC

Run habibi -p "…" for a one-shot response, or habibi --rpc for a persistent instance. RPC is newline-delimited JSON on stdin/stdout: not HTTP and not JSON-RPC 2.0. It opens no network port.

habibi --rpc
# Send one UTF-8 JSON object per line:
{"id":"start","method":"prompt","params":{"text":"Inspect the repository"}}
{"id":"status","method":"status"}

Keep stdin open. Stdout contains protocol records; stderr carries diagnostics. Drain both continuously. Requests are at most 1 MiB and use string or numeric correlation IDs—not idempotency keys.

{"id":"start","result":{"accepted":true}}
{"id":"other","error":{"message":"Agent busy; use steer or follow_up"}}
{"event":"text_delta","text":"Here is what I found…"}
MethodParameters / behavior
prompt{"text":"…"} — start while idle.
steer{"text":"…"} — queue a correction while running.
follow_up{"text":"…"} — queue a turn; starts immediately if idle.
approve{"call_id":"…","allow":false} — answer a pending approval once.
statusSession ID, busy/stopping state, queued work, pending approvals.
stopCancel work and clear queues; keep the instance alive.
shutdownAcknowledge, cancel/drain work, then exit.

Lifecycle

The first event is ready (protocol version 1, session ID, journal, approval mode). A run emits events such as run_started, text_delta, permission, tool_started, tool_finished, run_finished, and idle. Responses and events can interleave. Use idle as the completion boundary; accepted only means queued. Startup failures can emit idle without run_started.

Text is nonblank and at most 524288 UTF-8 bytes; the context budget may impose a smaller effective limit. Steering and follow-up queues each hold at most 32 entries. Closing stdin cancels active work and discards pending queues. Completed side effects are never rolled back.

Tools need individual approval unless --yolo was explicitly passed; saved TUI YOLO is ignored. Code-mode child calls also need approval. Never automatically approve untrusted permission events.

Minimal Python client (denies tools)
import json
import subprocess

p = subprocess.Popen(
    ["habibi", "--rpc"],
    stdin=subprocess.PIPE,
    stdout=subprocess.PIPE,
    text=True,
    # stderr is inherited so it cannot fill an unread pipe.
)

def send(request_id, method, **params):
    p.stdin.write(json.dumps({"id": request_id, "method": method, "params": params}) + "\n")
    p.stdin.flush()

print(json.loads(p.stdout.readline()))  # ready
send("start", "prompt", text="Explain the repository")
for line in p.stdout:
    message = json.loads(line)
    if message.get("event") == "text_delta":
        print(message["text"], end="", flush=True)
    elif message.get("event") == "permission":
        call_id = message["call"]["id"]
        send("approval-" + call_id, "approve", call_id=call_id, allow=False)
    elif message.get("event") == "idle":
        send("exit", "shutdown")
# Continue draining until EOF; shutdown acknowledges before it finishes cleanup.
p.wait()

Control a running instance

Every TUI, one-shot, and RPC instance also exposes a private Unix socket. The startup transcript or stderr shows the path. Discover habibi-<pid>-*/instance.json under XDG_RUNTIME_DIR, or the system temporary directory when unset. Metadata includes PID, session ID, journal, and socket.

The socket accepts the same request methods and ID-correlated responses as stdio, but is request/reply only, not an event stream. Poll status to monitor work. Disconnecting a socket client does not cancel the agent.

import json, socket

with socket.socket(socket.AF_UNIX) as client:
    client.connect("/path/from/startup/control.sock")
    stream = client.makefile("rwb")
    request = {"id": 1, "method": "steer",
               "params": {"text": "Focus on the failing test first."}}
    stream.write(json.dumps(request).encode() + b"\n")
    stream.flush()
    print(json.loads(stream.readline()))

Directories are mode 0700 and sockets 0600. Other processes running as your user can control the agent and approve tools. Normal exit removes discovery files; stale files after a forced kill are not proof of a live instance. Limits: 16 clients, 32 buffered requests, 1 MiB per request.

Footprint & measurements

The homepage numbers come from the published v0.8.0 x86-64 Linux musl binary, tested locally on an Intel Core i9-9900K. They are warm-cache measurements of an idle Ollama-configured TUI, without making model requests.

MeasurementResult / method
Uncompressed stripped binary16.21 MiB
Idle resident memory10.03 MiB · median of 5 runs
TUI first paint5.09 ms · median of 5 runs
--help startup0.58 ms · median of 20 runs

First paint includes process launch and local session creation. RSS is the agent process only: it excludes Ollama, MCP servers, tools, and other child processes. Active sessions and large contexts use more memory. These are not cold-start guarantees, model-response timings, comparisons against Pi, or a 50-agent concurrency test.

# Linux PTY checks and warm measurements; no provider credentials needed
python3 scripts/smoke.py /path/to/release/habibi

Habibi uses a native Rust executable, no Node.js runtime, no provider-agent subprocess, and no Habibi daemon. Code mode embeds QuickJS. Ollama still requires its server; explicitly configured MCP programs may start their own processes.

Safety & current limits

Approval is not sandboxing. Shell commands and MCP programs run with your account’s access. Journals and credentials are private files, not encrypted storage. Journals may include sensitive conversation content and image data. Treat socket access as full control of the agent.

Private secrets are memory-only and redacted from captured output, but this is not protection against malicious tools or model-directed exfiltration. Cancellation cannot undo completed mutations.

Subscription adapters are experimental and not guaranteed provider-approved. Review provider terms. macOS binaries require macOS 15+ and are unsigned/not notarized. The Rust API and journal format are prototype-level. No built-in subagents, repository indexer, or API-key providers.
