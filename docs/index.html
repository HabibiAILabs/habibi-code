Install with one command

Installs to ~/.local/bin. No sudo. SHA-256 verified. Read the installer first or download an archive.

Less machinery. More agency.

Native all the way

A Rust binary and an embeddable engine. No Node.js runtime, Habibi daemon, or provider-agent subprocess. Ollama uses its own server.

A conversation, not a log dump

Compact tool summaries, styled responses, scrollback, multiline input, and configurable status elements.

Stay in the loop

Steer an active run, queue follow-ups, interrupt with Esc, and resume your saved session later.

Your permission policy

Approve each tool by default. Explicit YOLO mode is available for trusted work and remains active on session resume. Approval is not a sandbox.

Skills when you need them

Discover Agent Skills metadata automatically. Load full instructions with approval and keep sticky snapshots through compaction and resume.

See what the agent sees

Inspect active context and recorded tool calls in searchable tabs. A bouncing-ball prompt indicator keeps progress visible without cluttering the footer.

New in v0.3.1

Slash commands stay available while the agent works. Open /inspect, /settings, /model, /models, /help, or /update without interrupting a run. Type / for matching suggestions and press Tab to complete or cycle matches.

Settings changes apply after the current run finishes, before queued follow-ups. In-flight requests and tool permissions stay unchanged. /compact, /quit, and /exit still require an idle agent.

Bring your Agent Skills

Default search directories are ~/.agents and workspace .agents. Both <directory>/skills/<name>/SKILL.md and <directory>/<name>/SKILL.md are supported. Workspace skills override home skills.

Frontmatter enters context automatically; the approval-gated load_skill tool reads full instructions on demand. Sticky skills are ON by default and retain approved snapshots through compaction and resume. Skill content is untrusted reference data, not higher-priority instructions.

Edit the ordered directory list and sticky toggle in /settings, or override directories for a new session:

habibi --skill-dir '~/.agents' \
  --skill-dir .agents \
  --skill-dir ./team-skills
habibi --no-sticky-skills

Metadata and active sticky snapshots count toward the context byte budget. Skills are never downloaded automatically.

Inspect context and calls

Run /inspect at any time. During execution it shows the latest context-boundary snapshot; close and reopen to refresh while the agent keeps running. The Context tab breaks down the byte budget and shows the system prompt, skill context, tool definitions, and active messages. Counts are bytes, not tokens or an exact provider request.

The Tool calls tab shows calls since the latest user message. Toggle all session calls to browse arguments, recorded results, and errors—including calls before compaction.

Tab / 1 / 2 switches tabs; ↑/↓ selects; PgUp/PgDn or the wheel scrolls details; / searches; a toggles latest/all calls; Esc/q closes. Inspection never executes or approves tools.

Keep the loop under your control

CommandWhat it does
/inspectBrowse context and tool calls in a read-only modal, even during execution.
/compactSummarize active history without deleting original journal records. Automatic compaction defaults to 80% of the byte budget.
/settingsEdit model, context budget, auto-compaction, turn cap, skill directories, sticky mode, permissions, and status elements. Changes saved during a run apply when it finishes. 0 model turns means unlimited.
/modelsList bundled subscription choices or discover installed Ollama models.
/modelChoose with Ctrl-N/P or type a model ID; save it as a user default.
/helpReview commands, steering, follow-ups, approval keys, and cancellation.

A subtle bouncing ball in the prompt border shows Thinking, Responding, Executing tool call, or Compacting context. It pauses for approval and stops when idle. Enter steers an active run; Alt-Enter queues a follow-up; Esc interrupts.

Start a session

habibi login codex
habibi --provider codex

# Experimental Claude subscription adapter
habibi login claude
habibi --provider claude

# Local Ollama (no login; install a tool-capable model first)
habibi models ollama
habibi --provider ollama --model qwen3:8b

# Pick up where you left off
habibi --resume /path/to/session.jsonl

Open the login URL in your browser. For SSH, paste the failed callback URL into the private login prompt—not chat. Account access and model availability are controlled by the provider.

Let your terminal follow the work

Habibi supports the OSC 7501 Program Status Protocol: working, waiting for permission or login, done, error, and idle after cancellation. Status metadata uses fixed messages, never prompts, file paths, tool arguments, or credentials. Set HABIBI_NO_PROGRAM_STATUS=1 to disable it. Terminal presentation depends on support; Rex UI behavior has not been live-tested.

Upgrading to v0.3.1

Reinstall after the release is published and restart Habibi. Existing journals remain readable; Ollama journals require v0.3.0 or later. Saved model choices are preserved. Apply /model or /settings once to establish user defaults.

Enabling YOLO in settings now also enables it for future new sessions in every directory. The confirmation warns about this scope. Disable it and Apply to restore Ask defaults. Existing sessions keep their saved permission mode on resume. YOLO approves all tools, including unsandboxed shell commands.

Experimental software, clear limits

Subscription adapters are experimental, not verified provider-approved integrations. Real-account authentication and inference have not yet been verified for this prototype. Claude compatibility uses Claude Code-specific identity. Review provider terms. There is no automatic API-billing fallback.

Shell commands run with your account’s access. Saved credentials and sessions are plaintext and may contain sensitive data. Only approve operations you trust.
