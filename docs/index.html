Less machinery. More agency.

Native all the way

A Rust binary and an embeddable engine. No Node.js runtime, Habibi daemon, or provider-agent subprocess. Ollama uses its own server. Code mode embeds QuickJS; configured MCP programs may run as children.

A conversation, not a log dump

Compact tool summaries, styled responses, scrollback, multiline input, and configurable status elements.

Stay in the loop

Steer an active run, queue follow-ups, interrupt with Esc, and resume your saved session later.

Your permission policy

Approve each tool by default. Explicit YOLO mode is available for trusted work and remains active on session resume. Approval is not a sandbox.

Skills when you need them

Discover Agent Skills metadata automatically. Load full instructions with approval and keep sticky snapshots through compaction and resume.

See what the agent sees

Inspect active context and recorded tool calls in searchable tabs. A bouncing-ball prompt indicator keeps progress visible without cluttering the footer.

New in v0.7.4

Default prompt cleanup: removed the blanket tool-approval instruction. Runtime approval enforcement and Ask/YOLO behavior are unchanged. New sessions use the updated prompt; resumed sessions keep their saved prompt.

Native private secrets: masked entry, private stdout capture, confirmed local reveal/copy, and buffered shell execution with exact-value redaction. Browse, show, or forget session-only secrets with /secret. Normal tool approvals still apply. Secrets stay out of model context and journals; private entry and reveal require the terminal. This is transcript hygiene, not a sandbox or protection against a malicious model. Usage and security limits.

macOS RAM indicator fixed: the status bar now reports current-process resident memory on macOS, matching Linux. No extra permissions or subprocesses are needed.

Native image reading: read PNG, JPEG, GIF, and WebP with a vision-capable model. Image attachments work through code mode and session resume. Ollama checks reported vision support; PDFs and other binary files receive extraction guidance. Existing approvals and the 2 MiB file limit remain in place.

Session browser: /resume lists sessions for your current folder, newest first, with a first-user/latest-message preview beside the list. Type to search, use arrows or wheel to select, Enter to resume, and Esc to close. Saved settings and permissions are restored.

Terminal-style prompt editing: Ctrl-C clears a nonempty draft first; Up/Down recalls editable prompt history; Ctrl-A/E and Alt-B/F navigate lines and words. Mouse scrolling stays enabled. Use your terminal’s selection override (commonly Shift-drag) and copy shortcut to copy transcript text.

Authenticate HTTP MCP servers directly from /mcp with a, or run habibi mcp login SERVER. Browser OAuth includes hidden callback input, cancellation, private endpoint-bound credentials, and automatic refresh. Explicit bearer-env configuration still takes precedence.

Also included from v0.4.0: Control any running instance, compose tools with code mode, connect trusted MCP servers, and recover from transient provider errors.

Headless and local control

habibi -p "…" streams text and exits; habibi --rpc serves persistent JSON Lines on stdin/stdout. Every instance—including the TUI—also exposes a private Unix socket for status, prompts, steering, follow-ups, approvals, cancellation, and shutdown.

The startup output shows the socket path. Socket clients use request/reply JSON Lines; disconnecting does not cancel work. One-shot runs still deny tools unless --yolo is explicit. Protocol and examples →

MCP and embedded code mode

Use /mcp to configure local stdio or remote Streamable HTTP servers in a form, without editing JSON. MCP and code mode are enabled by default and independently toggleable in /settings. Only explicit user MCP configuration is loaded, never repository configuration.

Embedded QuickJS lets the model compose tools with bounded parallelism. Approving a script does not approve its child calls. Configured MCP programs and shell tools are trusted and not sandboxed.

Resilient requests, better completion

Transient provider failures retry up to five times with cancellable backoff. Partial response streams are never replayed automatically. Type / to see commands and discovered skills above the prompt; use ↑/↓ to select and Tab to complete.

Commands remain available during execution. Saved settings apply after the current run, leaving in-flight permissions unchanged.

Bring your Agent Skills

Default search directories are ~/.agents and workspace .agents. Both <directory>/skills/<name>/SKILL.md and <directory>/<name>/SKILL.md are supported. Workspace skills override home skills.

Frontmatter enters context automatically; the approval-gated load_skill tool reads full instructions on demand. Sticky skills are ON by default and retain approved snapshots through compaction and resume. Skill content is untrusted reference data, not higher-priority instructions.

Edit the ordered directory list and sticky toggle in /settings, or override directories for a new session:

habibi --skill-dir '~/.agents' \
  --skill-dir .agents \
  --skill-dir ./team-skills
habibi --no-sticky-skills

Metadata and active sticky snapshots count toward the context byte budget. Skills are never downloaded automatically.

Inspect context and calls

Run /inspect at any time. During execution it shows the latest context-boundary snapshot; close and reopen to refresh while the agent keeps running. The Context tab breaks down the byte budget and shows the system prompt, skill context, tool definitions, and active messages. Counts are bytes, not tokens or an exact provider request.

The Tool calls tab shows calls since the latest user message. Toggle all session calls to browse arguments, recorded results, and errors—including calls before compaction.

Tab / 1 / 2 switches tabs; ↑/↓ selects; PgUp/PgDn or the wheel scrolls details; / searches; a toggles latest/all calls; Esc/q closes. Inspection never executes or approves tools.

Keep the loop under your control

CommandWhat it does
/mcpManage trusted local and remote MCP servers while idle; a authenticates HTTP servers, l removes local OAuth credentials. Connections begin on the next prompt.
/inspectBrowse context and tool calls in a read-only modal, even during execution.
/compactSummarize active history without deleting original journal records. Automatic compaction defaults to 80% of the byte budget.
/settingsEdit model, context budget, auto-compaction, turn cap, skill directories, sticky mode, MCP/code mode, permissions, and status elements. Changes saved during a run apply when it finishes. 0 model turns means unlimited.
/modelsList bundled subscription choices or discover installed Ollama models.
/modelChoose with Ctrl-N/P or type a model ID; save it as a user default.
/helpReview commands, steering, follow-ups, approval keys, and cancellation.

A subtle bouncing ball in the prompt border shows Thinking, Responding, Executing tool call, or Compacting context. It pauses for approval and stops when idle. Enter steers an active run; Alt-Enter queues a follow-up; Esc interrupts.

Start a session

habibi login codex
habibi --provider codex

# Experimental Claude subscription adapter
habibi login claude
habibi --provider claude

# Local Ollama (no login; install a tool-capable model first)
habibi models ollama
habibi --provider ollama --model qwen3:8b

# Headless output (tools denied unless --yolo is explicit)
habibi -p "Explain the architecture"

# Persistent stdio JSON Lines RPC
habibi --rpc

# Pick up where you left off
habibi --resume /path/to/session.jsonl

Open the login URL in your browser. For SSH, paste the failed callback URL into the private login prompt—not chat. Account access and model availability are controlled by the provider.

Let your terminal follow the work

Habibi supports the OSC 7501 Program Status Protocol: working, waiting for permission or login, done, error, and idle after cancellation. Status metadata uses fixed messages, never prompts, file paths, tool arguments, or credentials. Set HABIBI_NO_PROGRAM_STATUS=1 to disable it. Terminal presentation depends on support; Rex UI behavior has not been live-tested.

Upgrading to v0.4.0

Reinstall after the release is published and restart Habibi. Existing journals remain readable. New code-mode child-call audit records require v0.4.0 or later; older binaries cannot read those records. Saved model choices are preserved. Apply /model or /settings once to establish user defaults.

Enabling YOLO in settings now also enables it for future new sessions in every directory. The confirmation warns about this scope. Disable it and Apply to restore Ask defaults. Existing sessions keep their saved permission mode on resume. YOLO approves all tools, including unsandboxed shell commands.

Experimental software, clear limits

Subscription adapters are experimental, not verified provider-approved integrations. Real-account authentication and inference have not yet been verified for this prototype. Claude compatibility uses Claude Code-specific identity. Review provider terms. There is no automatic API-billing fallback.

Shell commands and configured MCP programs run with your account’s access. Private control sockets grant full agent control to other processes running as your user. Saved credentials and sessions are plaintext and may contain sensitive data. Only approve operations you trust.
